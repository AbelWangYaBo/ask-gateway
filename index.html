01

一次请求，一条完整台账

t₀ · queued

凭 Key 入账

请求持平台 Key 进入网关，审计行立即建立——持有人、模型、客户端 IP、完整 prompt。配额三重闸门依次校验：RPM、日预算、并发。

t₁ · acquired

有界弹性 runtime 池

从 DSH 常驻进程池借出执行位。上游 Key 按组轮换、熔断隔离；deepseek-flash 与 deepseek-v4-pro 全部经由官方 Harness SDK 驱动。

t₂ · thinking / web_search

过程事件逐条落库

思考文本、联网搜索调用、工具事件按序号完整入库，同时以 x-dsh-event 实时推给流式客户端——过程不空白、事后可回放。

t₃ · text

最终回答与多轮对话

回答全文归档，并自动归入该用户的对话体系：API 与门户 chatbot 同源，支持从任意消息点反复分叉平行分支。

t₄ · usage → cost

计费快照冻结

按 token 分类（命中/未命中输入、输出、搜索次数）逐项计价，定价快照随账入库——此后改价、停用、加优惠，历史账单永远不变。

权重 · priority

同时刻多条规则匹配时大者胜：常规价权重 0，临时优惠权重 1——优惠期整体覆盖常规，想保留峰谷差异就各档分别建高权重规则。

周期 · effective_from / to

官方发调价公告，立刻录入未来价，到点自动切换；临时优惠到期自动回落。不用人工守着时间改价，也不会忘了收尾。

快照冻结

每条 usage 落库时冻结当时规则全文。历史费用只读——若需修正，走专门的重算脚本，永远不会因为改规则而悄悄变账。
